Security

Do not take our word for it.

Every site says your files are safe. Here is how to check ours.

Check it yourself, in a minute.

Open any tool on this site, press F12 to open your browser's developer tools, and choose the Network tab. Then pick a PDF and use it. Watch the list: the page loads its own code and fonts when you arrive, and after that nothing goes out. No upload, no request carrying your file, nothing to a third party.

Try the same thing on any other free PDF site and watch your document leave.

Why it cannot happen by accident.

Not sending your file is a promise. Being unable to send it is a fact, and that is what this site is built on. Every page arrives with a Content Security Policy, a set of rules your browser applies to the page whatever the page tries to do. Ours contains this:

connect-src 'none'

That single line tells your browser to refuse every outgoing request this page might make: uploads, background requests, connections of any kind. Not to warn about them, not to ask, but to refuse. If a bug or a bad change ever tried to send your document somewhere, the browser would stop it before it left your machine.

You can see the rule for yourself in the same developer tools: the Network tab, the document request, and the response headers.

What that costs us.

This is worth saying plainly, because it is the trade behind everything here. That rule means this site can never carry analytics, advertising, error reporting or any third party script, since all of those work by sending data somewhere. We gave those up deliberately. It is why we cannot tell you how many people use each tool, and why there is nothing to sell to anyone.

The rest of the rules.

  • Scripts from here only. No code is loaded from anywhere else, so there is no other company whose bad day becomes yours.
  • No inline scripts, no eval. This closes off the class of bug behind a known vulnerability in PDF rendering, where a crafted document could run code in your browser.
  • No framing. Nobody can put this site inside their own page and collect what you do on it.
  • No forms that post anywhere. There is no address on the server that accepts a file, so there is nothing to send one to even by mistake.

What the server actually does.

Very little. It sends you the page and the code that runs in it, and that is the end of its involvement. It has no route that accepts a file, no database, and no record of who visited. Turning it off would stop new people arriving, but would not touch the work of anyone already here.

Why the size limit is what it is.

Most free PDF sites cap you at fifteen or a hundred megabytes, and that cap is a business decision: a larger file is what the paid plan is for. Ours is not. The work happens on your device, so the limit is however much your browser can hold at once, and the figure shown on each tool page is worked out from your own machine rather than chosen by us.

A desktop or laptop usually manages several hundred megabytes. A phone manages less, because it has less memory and is stricter about it. That is also why there is no daily limit and no queue: your computer does the work, so there is nothing of ours to run out.

Where this is weakest.

Being honest about the limits is more useful than claiming there are none.

  • You are trusting that the code you receive is the code we meant to send. That is true of every website, and the usual defence is to publish the source so anyone can compare it.
  • A browser extension you have installed can read any page you open, including this one. Nothing a website does can prevent that.
  • If your own device is compromised, no promise made by a web page helps you.

None of these are unique to us. They are worth knowing because a site that claims perfect safety is telling you something false.
